# 子代理工作台

在当前会话里直接派发、观察、接管并行子代理。派发默认走 **fork**：子代理继承本会话已完成的轮次，后台并行，完成后把结果以完成通知送回主会话。

## 用法

- 头部「＋ 子代理」：打开右侧「子代理」面板（右栏 Tab）。
- 工作台「分支」Tab：侧栏只放操作——选择「导出自」会话、勾选提交、选择「导入到」目标、完整/凝练/引用导入；右上角「视图」用浮窗展示 fork 时间线（主会话进度 + 仅 fork 节点，点节点查看对应会话），不挤占侧栏宽度。导入不唤醒目标，下次任务读取。
- `/fork [--detach] [--name <英文名>] -- <任务>`：命令行派发一个继承上下文的子代理；不填名字自动 `agent-N`。
- `/spawn [--detach] [--name <英文名>] [--model <provider/model>] -- <任务>`：派发一个全新上下文的子代理。

面板列表直接读 `subagentCatalog` 投影，分支视图读 `branchIndex` 投影，实时同步；没有手动刷新按钮，也不执行命令，不会在主会话里留下 JSON 回执。

> 名称是子代理的地址，只接受 1–32 个小写英文字母、数字或连字符，不支持中文，也不能叫 `lead`；UI 因此不提供名称输入，自动命名。中文任务描述会作为面板里的说明显示。

### 回报模式

- 「完成后回报主会话」关（默认）：独立运行，结束不发完成通知；开：结束时完成通知回主会话。
- 关：`--detach` / `delivery: 'caller'`，子代理独立运行，不向主会话发完成通知；
- 行内「总结」：让子代理用 `send_message` 把总结发给 lead。

工作台整行点击可打开子会话（在右侧栏新 Tab）；行内「停止」（只停当前轮；未运行时禁用）、「总结」（已完成的可续聊行出现）;不需要手动刷新。

## 边界

- fork 的种子是**已完成轮次**的快照：当前进行中的这一轮不会带上，之后父会话的新轮次也不会同步。
- 子代理权限在创建时固定，需要审批的操作会被自动拒绝；想让子代理写文件，先把主会话切到对应权限模式。
- 并发上限默认 8（插件 → 子代理 可调整），深度默认 1。
- 本版本是 demo：状态由 `subagentCatalog` 投影读取，失败/等待你处理的状态尚未区分；行内回复与 token/耗时展示在后续版本补充。
- 面板停靠在右侧栏 Tab（`sidebar.right.pane.tab`），与主会话共用同一份会话状态。
